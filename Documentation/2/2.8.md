# 2.8 - The Pool System

The Pool System can be used to spawn 'free' objects with scripts that inherit `MonoBehaviour` and `IPoolable`. This greatly reduces the overall CPU utilisation from spawning `GameObject`s.

---

### Spawning Game Objects

Using `Spawn<T>(prefab) where T : MonoBehaviour, IPoolable`, the Pool System gets the type of T and calls `GetPool(type)` which creates a pool of the type parameter, or returns one if one already exists.

If the count of the pool `singular` is greater than 0, the object of type T is dequeued from it.

Otherwise, the prefab of the function parameter is instantiated, and attempts to get component of type T, returning null if there is no component of type T on the prefab.

Then, the script attached to the object (`obj`) calls `OnSpawn()`, and the `gameObject` calls `SetActive(true)` before the `obj` is returned.

---

### Reclaiming Game Objects

Using `Reclaim<T>(T obj) where T : MonoBehaviour, IPoolable`, the Pool System gets the script of type T named `obj` and calls `OnReclaim()` and `OnReset()` before disabling the `GameObject`.

Then the queue of the type of `obj` attempts to enqueue `obj` onto a `Queue<IPoolable>` called `singular` using `GetPool(type)`.
