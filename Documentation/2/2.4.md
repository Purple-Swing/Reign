# 2.4 - The Save System

The Save System is another key element of what makes Reign great.

---

### GameData

The `GameData` class allows for the programmer to define custom variables with default values in a constructor which are set to the said values when the file is first created.

---

### SaveFileHandler

Save files are encrypted, `.json` formatted files that get stored in the application's `persistentDataPath` using the `SaveFileHandler` script in the `SaveSystem` class.

The `SaveFileHandler` has the task of encrypting plaintext and decrypting the cipher it is given, as well as saving and loading the save file to and from the `persistentDataPath` directory.

This is done using `SaveAsync(GameData data)`, its synchronous alternative `SaveSync(GameData data)` and `LoadAsync()`.

---

### GameCertificates Linkage

Inside `GameCertificates`, a large section is dedicated to how the `SaveSystem` class should function, under 'Save System'.

`GameCertificates` for the Save System have the following fields:

- `SAVE_SYSTEM_ENABLED`: decides if the `SaveSystem` should save or load inside your application.
- `SAVE_ENCRYPT`: tells the `SaveFileHandler` if saves should be encrypted 
- `SAVE_ON_QUIT`: tells the `SaveSystem` if it should save `OnApplicationQuit()`
- `SAVE_FILE_DIRECTORY`: the name of the save file, with the filename extension
- `SAVE_PASSWORD`: the password to encrypt and decrypt data with
- `SAVE_SALT`: the salt for encrypting and decrypting data
- `SAVE_ITERATIONS`: how many times the encryption or decryption should try to scramble the data

---

### Loading

> Scene Setup

The `SaveSystem` class calls `RunSetup()` when the active scene is changed within Unity's SceneManager.

`RunSetup()` attempts to `await SetupAsync()` where it will throw an exception if there is any reason it goes wrong.

`SetupAsync()` yields until `Reign.CurrentGameCertificates` isn't null, then checks if the `SAVE_SYSTEM_ENABLED` flag is true before running `RefreshHandlers()` (which assigns all of the `MonoBehaviour`s of type `IDataHandler` to a variable `dataHandlers`) and calling `LoadGameData()`.

> Loading the GameData

`LoadGameData()` checks if the `SAVE_SYSTEM_ENABLED` flag is true before awaiting the `SaveFileHandler`'s `LoadAsync()` method, assigning the new data to a variable `gameData`. Using a null-coalescing operator to create new `GameData` if the current save file doesn't exist.

Then for every one of the present `IDataHandler`s, their `LoadData(GameData data)` function is called.

---

### Saving

The `SaveGameDataSync()` or `SaveGameDataAsync()` subprograms function exactly the same, except one awaits the save and one doesn't. 

Both check if the `SAVE_SYSTEM_ENABLED` flag is true before finding every one of the present `IDataHandler`s and executing their `SaveData(ref GameData data)` functions.
