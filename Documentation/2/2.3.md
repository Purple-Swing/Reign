# 2.3 - The Input System

The Input System is integral to Reign, it serves as the bridge between the new Input System package from Unity and your game, helping it to be less confusing and obtuse.

---

### Inner Workings

Inputs from the `ActiveInputMap` in the `ProjectWideInputActions` asset are cached in the input dictionary when they are rebuilt, this can be either when the active input map is changed using `UpdateActiveInputMap()`, in `Validate()` or using the plain `RebuildCache()` function. Inputs are saved in the dictionary with string aliases mimicing the respective Input Action name.

---

### Reading Values

Using the `GetValue<T>(name)` function, the Input System allows you to read the value of type T using the string name from the cached inputs, similar to `ReadValue<T>()` with any referenced `InputAction`.

For example, reading the Move vector (given by default in the Input System package) can be done via this line of code:

```
var move = InputSystem.Instance.GetValue<Vector2>("Move");
```

---

### Get Button

Using the `GetButton(name, inputType, requireAllBindings)` function allows for detection of buttons with the names of them in the dictionary.

Input Type is the enum that mimics the Interactions drop down in the refered action. It can be one of three states: `PRESSED`, `PRESSING` and `RELEASED`.

Each of these have different behaviours:

- `PRESSED` fires a signal when the button is **pressed down**.
- `PRESSING` fires a signal continuously when the button is **being pressed**.
- `RELEASED` only fires a signal when the current button that is down has been **released**.

---

### Why InputType?

An example for the reason we use the `InputType` enum and not the provided  one in the `InputActions`:

Imagine you want to have a button that skips a cutscene. On one occasion you have to hold the button down, but on another you just press it once.

With `InputActions`, this would be done by creating two actions with the same bindings, but this is wildly inefficient and creates bloat within the menu.

But with the Input System, using `GetButton("SkipCutscene", InputType.PRESSED)` and `GetButton("SkipCutscene", InputType.PRESSING)`, you have freedom to change them on demand with minimal external changes outside of your script, and access to more than one way to use one action.

For this reason, NEVER change the enum inside of the `InputActions` unless you are certain that you will only use it in one way.
